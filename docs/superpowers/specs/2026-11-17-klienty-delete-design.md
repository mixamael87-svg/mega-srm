# «Клієнти»: удаление клиентов и ФОП — короткий дизайн

Дата: 2026-11-17 · Утверждено владельцем в чате

**Зачем:** владелец хочет удалять клиентов насовсем (не архив), с двойным предупреждением. В SalesDrive ничего не меняется — приложение только читает оттуда.

**Подходы:** А ✅ — удаление насовсем, документы остаются в истории с названием из снимка шапки и пометкой «(видалено)»; Б — запрет удаления при наличии документов (отвергнуто владельцем: «насовсем»); В — мягкое удаление/архив клиента (отвергнуто: «насовсем»).

**Как:**
- `Document.clientFopId` становится необязательным, `onDelete: SetNull`; `ContactDefault` удаляется каскадом вместе с ФОП.
- История: если связи нет — `clientName` = первая строка `headerJson.recipient` последней версии + « (видалено)»; поиск по истории находит и такие документы по тексту получателя не требуется (решение исполнителя: ищем только по живым связям).
- Перегенерация документа, у которого ФОП удалён, работает как обычно: менеджер выбирает нового получателя.
- API: `DELETE /api/clients/:id`, `DELETE /api/client-fops/:id` — только admin (403 менеджеру); `GET /api/clients/:id/usage` → `{ fops, documents }` для текста предупреждения.
- UI (только admin видит «Видалити»): 1) красная плашка «Видалити клієнта X і N ФОП? По ньому є M документів — вони залишаться в історії, але без зв'язку з клієнтом.» [Так, видалити] [Скасувати]; 2) `confirm('Остаточно видалити X? Це не можна скасувати.')`. Для ФОП — то же с «ФОП X».

**Решения исполнителя:** удаляет только admin; отдельные ФОП тоже удаляются; архив остаётся.
