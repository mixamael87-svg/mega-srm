# Наклейки по заявке SalesDrive + редактируемый список — дизайн

Дата: 18.11.2026. Статус: утверждён владельцем («приступай», 18.11 10:22). Дополняет `2026-11-17-naklejky-design.md`.

## Зачем
Владелец хочет печатать наклейки сразу по номеру заявки SalesDrive, не формируя накладную, и перед печатью видеть и править список.

## Подходы
1. Поле «№ заявки» на вкладке «Наклейки». 2. **Кнопки на «Новий документ» после загрузки заявки — выбран владельцем.**
Печать: GET по номеру (без правки) — отклонено, т.к. список редактируется; **POST списка → PDF — выбрано**.

## Как работает
- «Новий документ»: после загрузки заявки — блок «Наклейки» с кнопками «Друкувати: <набір>» (все наборы). «Історія»: прежние кнопки у активной накладной открывают то же окно.
- Окно «Друк наклейок»: таблица Артикул · Назва · К-ть · Статус. Строки: по артикулу (цвета «Мікс» суммированы), порядок — первое появление. Статус: «є наклейка» (+ «Частина 2» если есть), «немає наклейки», «не друкувати». К-ть редактируется только у «є наклейка» (0 = не друкувати), строку можно убрать (×). «+ Додати артикул» — 4 цифры + к-ть; статус показывается из набора. Итог «Буде надруковано N наклейок» считается в окне (с учётом «Частини 2»). «Друкувати» → PDF в новой вкладке.
- API: `GET /api/orders/:id/labels?set=` и `GET /api/documents/:id/labels?set=` → `{ setName, title, rows: LabelRow[] }`; `POST /api/label-sets/:id/print { title, items: [{ sku, qty }] }` → PDF `Наклейки_<title>_<набір>.pdf`. Сервер сам отбрасывает артикулы без наклейки и «не друкувати». `LabelRow = { sku, name, qty, status: 'ok'|'missing'|'noPrint', extra: string|null }`.
- Права: все вошедшие. Документ — только активная накладная (`LABELS_NOT_ALLOWED`). Заявка не найдена — 404 `ORDER_NOT_FOUND`.
- Лимит SalesDrive: открытие окна = 1 запрос заявки; печать запросов к SalesDrive не делает.

## Не меняется
Расчёт страниц (`planLabels`), PDF, база наклеек, кнопки в «Історії».
