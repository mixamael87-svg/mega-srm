# «Наші ФОП»: удаление — короткий дизайн

Дата: 2026-11-17 · Утверждено владельцем в чате (вариант 1)

**Зачем:** admin хочет убирать наших ФОП. Удаление насовсем вместе со счётчиком рахунків при повторном заведении того же ФОП дало бы дубли номеров (анти-цель модуля 1).

**Подходы:** 1 ✅ — насовсем только ФОП без документов; с документами — скрыть (архив): нет в выборе постачальника, история и счётчик целы, можно вернуть. 2 — насовсем всегда (риск дублей номеров; отвергнут).

**Как:** `OurFop.archived` (default false). Удаление (admin, `DELETE /api/fops/:id`): нет документов → удалить ФОП и его `InvoiceCounter`; есть → `archived = true`, `isDefault = false`. `PATCH /api/fops {id, archived:false}` — вернуть. Выбор постачальника и ФОП по умолчанию на «Новий документ» — только не архивные. Формирование с архивным ФОП → 409 `FOP_ARCHIVED` «Постачальник в архіві». Предупреждения: плашка (текст зависит от наличия документов) → `confirm`. В «Наші ФОП» архивные показаны с пометкой и кнопкой «Повернути».
