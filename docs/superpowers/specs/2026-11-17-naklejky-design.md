# MEGA SRM · Наклейки — дизайн

Дата: 17.11.2026. Статус: утверждён владельцем 17.11.2026.

## Зачем

Сейчас наклейки на товар печатаются из BarTender 2016 Basic на Xprinter XP-420B: для каждого артикула свой файл `.btw`, оператор открывает файлы по одному и вручную набирает количество. Нужно: открыть видаткову накладну в MEGA SRM, нажать одну кнопку — и получить все наклейки по списку накладной в заказанном количестве; артикулы без наклейки не печатаются.

BarTender Basic нельзя запускать из другой программы (командная строка — только в Automation и выше), сайт работает в облаке (Render) и до принтера/папок на ПК не достаёт. Поэтому наклейки переезжают в MEGA SRM, а печать идёт через PDF и обычный диалог печати браузера.

## Цели

- Кнопка печати наклеек у накладной — отдельная для каждого набора наклеек.
- Количество — по артикулу, цвета одного артикула суммируются (наклейка одна на артикул).
- Нет наклейки в наборе / наклейка «не друкувати» → не печатается, оператор видит список пропущенного.
- Наклейки хранятся и правятся в MEGA SRM; BarTender больше не нужен.
- Перенос существующей базы (набор «Загальна», папка `D:\Наклейки`) без ручного перенабора.

## Не цели (сейчас)

- Печать без диалога (QZ Tray / помощник на ПК) — позже, когда печать проверена.
- Наборы «ФОП Кузнецов» и «ТОВ Кузкас» — заводятся тем же механизмом, наполнение позже (владелец: «начнем пока с 1 папки»).
- Наклейки на рахунок, на произвольный заказ без накладной, печать одной наклейки поштучно вне накладной.
- Пиксель-в-пиксель копия BarTender: перенос строк текста может отличаться.

## Анти-цели

- Неверный штрихкод или нечитаемый сканером — хуже, чем отсутствие наклейки.
- Напечатана наклейка, помеченная «не друкувати».
- Наклейка печатается не того размера / съезжает между этикетками.

## Решения владельца

1. Вариант «перенести наклейки в MEGA SRM + PDF» (из трёх: PDF / печать превью из .btw / только список для ручной печати в BarTender).
2. Три набора и три кнопки: «Загальна», «ФОП Кузнецов», «ТОВ Кузкас». Кнопка печатает только из своего набора, независимо от постачальника в накладной; из других наборов не подтягивает.
3. Начинаем с одного набора — `D:\Наклейки` = **«Загальна»**.
4. Подпапку `1400` не переносим (файлы сейчас пустые).
5. `0402` и `0402 без фут` — одинаковые, берём `0402`.
6. Наклейки «не друк» никогда не печатаются.
7. Серия 1200: на каждую штуку печатается своя наклейка (`1205-1` и т. д.) и сразу за ней общая «частина 2» (инструкция).

## Как это работает

### Данные

- `LabelSet` — набор: `id`, `name`, `sort`. Создаётся три: Загальна, ФОП Кузнецов, ТОВ Кузкас.
- `Label` — наклейка в наборе:
  - `setId`, `sku` (4 цифры; уникален в наборе; пусто для служебных наклеек вроде «частина 2»), `title` (для служебных — имя, напр. «Частина 2 (серія 1200)»);
  - `text` — текст наклейки (абзацы через перенос строки);
  - `align` — `center` | `left` (серия 1200 и «частина 2» — слева, остальные по центру);
  - `showMark` — знак відповідності в правом верхнем углу;
  - `barcode` — EAN-13; по умолчанию `ean13FromSku(sku)`, можно выключить (у «частина 2» штрихкода нет);
  - `noPrint` — «не друкувати»;
  - `extraLabelId` — наклейка, которая печатается сразу после этой на каждую штуку (1205 → «частина 2»).

### Печать с накладной

В «Історія документів» у каждой **активной видаткової накладної** — кнопки «Наклейки: <набор>» по одной на набор (порядок `sort`).

1. Берётся последний снимок строк накладной (`DocumentVersion.linesJson`).
2. Группировка по `sku`, количество суммируется; порядок — по первому появлению артикула в накладной.
3. Для каждого артикула: нет наклейки в наборе → в «Немає наклейки»; `noPrint` → в «Не друкувати»; иначе — `qty` раз наклейка (+ `extraLabel` после каждой).
4. Окно-сводка: «Буде надруковано N наклейок» + списки пропущенного (артикул, назва з накладної, кількість). Кнопка «Друкувати» открывает PDF в новой вкладке → Ctrl+P → Xprinter. Если печатать нечего — только сводка.
5. Дробное количество округляется вверх (на практике не встречается).

### PDF

- Страница 37,5 × 40 мм, одна наклейка на страницу, поля ~1,5 мм.
- Шрифт — жирный Arial-совместимый (Arimo/Liberation Sans Bold, свободная лицензия, вшит в PDF; Arial не распространяем).
- Текст: размер шрифта подбирается автоматически — максимальный, при котором текст влезает в область над штрихкодом (короткие наклейки — крупно, полные — мелко, как сейчас).
- Штрихкод EAN-13 рисуется векторно (без растра) по всей ширине, цифры под ним — как в текущих наклейках.
- Знак відповідності — чёрно-белая картинка, вырезанная из превью текущих наклеек, верхний правый угол.
- Генерация на сервере (`GET /api/documents/:id/labels?set=…`), PDF не хранится.

### Раздел «Наклейки»

Вкладка в меню. Выбор набора; список (артикул, начало текста, отметки «не друк», «+ частина 2»); поиск по артикулу и тексту. Карточка: поля из «Данные» + живой предпросмотр в масштабе (тот же рендер, что PDF). «Додати набір» — новая кнопка на накладных появляется сама.

Права: смотреть, печатать, создавать и править — все пользователи; удалять наклейку и набор — только admin, с подтверждением (как в «Клієнтах»).

### Перенос базы «Загальна» (разово, делает Claude)

1. Из каждого `.btw` достаётся встроенное превью (текст из `.btw` программно не читается — закрытый формат).
2. Распознавание текста (Tesseract, украинский) + сверка глазами Claude; штрихкод — по артикулу и сверка с цифрами на превью; знак, выравнивание — по превью.
3. Таблица «превью ↔ распознанный текст» владельцу на проверку.
4. После проверки — загрузка через одноразовый admin-импорт JSON (`POST /api/label-sets/:id/import`), повторный импорт не создаёт дублей (ключ `set + sku`).

Состав: 169 файлов в папке на 17.11 14:18 → без `1400` (5) и `0402 без фут` = 163; `2004 по шт не друк` → `noPrint`; `1205-1…1221-1` → артикулы 1205…1221 с `extraLabel` = «частина 2».

### Настройка принтера (разово)

В драйвере Xprinter XP-420B — размер бумаги 37,5 × 40 мм; в диалоге печати браузера — «Масштаб: 100% / фактический размер», без полей и колонтитулов. Инструкция — в README.
