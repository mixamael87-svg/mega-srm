# MEGA SRM — «Звіти клієнтів»: преобразователь отчётов и переоценка

Дата: 2026-11-19 · Статус: на утверждение владельцу (стороны документов — вручную, ответ 19.11)

## Зачем

Клиенты присылают отчёты о продажах и о фактических остатках в формате своей учётной программы: свои коды, свои названия, их цена закупки. Нужно:

1. **Преобразовать** такой отчёт в Excel в нашем виде: наш артикул, наше название, количество, цены.
2. **Переоценка** остатков клиента: загрузить отчёт об остатках → сформировать **накладну на повернення** (клиент «возвращает» остаток по старой цене) → проставить новые цены → сформировать **видаткову накладну** (те же товары обратно по новой цене). Товар физически не движется.

Цены у каждого клиента свои; новые цены пока вводятся **вручную** (решение владельца). Номер документа, магазин и прочие спорные поля — тоже вручную (владелец: «все вопросы вручную»).

## Образцы (получены 19.11)

Оба от **Family Toys**, учётная программа **Bagel** (`www.bagel.com.ua`), .xls (BIFF8, cp1251):

- **«Оборот по постачальникам»** 01.10–31.10.2026. Шапка: клиент, название отчёта, период, поставщик «Mega Zayka», затем блоки по **магазинам** («Магазин FAMILY TOYS ТЦ "LUXOR PLAZA"», «… ТЦ "Білочка"»), внутри — по категориям. Колонки: `Код` (их код), `Назва`, `Ціна закупки`, `Тип постачання`, `Штрих код`, остаток на начало, `Документи приходу`, `Документи роздрібного продажу`, `Документи продажу`, остаток на конец, `Дата ост. приходу`. Строки «Разом …» — итоги.
- **«Залишок товару по постачальникам»** на 02.11.2026. Те же магазины и категории. Колонки: `Код`, `Назва`, `Ціна закупки`, `Ціна продажу`, `К-сть`, `Сума закупки`, `Сума продажу`. **Штрихкода нет.**

Факты: в обороте 417 из 419 строк со **штрихкодом `48260770…`** (наш, из него — наш артикул, см. `ean13FromSku`); 2 строки — чужой штрихкод `4820288950011`. Все 202 кода из отчёта об остатках есть в обороте. Один товар может идти несколькими строками в одном магазине (разные партии) — складываются.

## Цели

1. Раздел **«Звіти клієнтів»**: выбрать клиента (из «Клієнти») и загрузить файл; формат и тип отчёта распознаются автоматически.
2. Таблица результата по выбранному магазину или по всем: наш артикул, наше название, количество(а), старая цена (из отчёта), **поле «Нова ціна»** (ввод вручную), суммы. Нераспознанные строки — отдельным списком с их кодом, названием, штрихкодом.
3. Соответствие **«код клиента → наш артикул»** запоминается для клиента (из строк со штрихкодом) и используется для отчётов без штрихкода. Нераспознанную строку можно сопоставить вручную (ввести наш артикул) — тоже запоминается.
4. Кнопки: **«Excel (наш формат)»**, **«Накладна на повернення»** (по старым ценам), **«Видаткова накладна»** (по новым ценам; доступна, когда новая цена заполнена у всех строк).
5. Документы — в «Історії», скачиваются повторно, анулюються, как остальные.

## Не входит

- Автоматические цены клиента (тип цены SalesDrive, прайс, наценка) — позже.
- Универсальная настройка колонок под любой формат (подход Б) — позже, если форматов станет много.
- Запись чего-либо в SalesDrive; хранение исходных файлов отчётов.
- Наклейки по документам переоценки (товар не движется).

## Анти-цели

- Товар клиента молча сопоставлен не с тем нашим артикулом.
- Строка отчёта молча потерялась (не попала ни в результат, ни в «нераспознано»), или повторы не сложились.
- Количество в накладной на повернення не равно остатку из отчёта.
- Документы переоценки ломают нумерацию или историю обычных документов.

## Подходы (выбран А, владелец, 19.11)

| | Подход | Плюсы | Минусы |
|---|---|---|---|
| **А ✅** | Готовый разбор под каждую учётную программу (сейчас Bagel), запоминание кодов клиента | Надёжно на «шапках», магазинах, итогах; быстро | Каждый новый формат — небольшая доработка |
| Б | Универсальная настройка колонок пользователем | Новые форматы без доработок | Больше работы; на сложных шапках ошибается |
| В | Отдельная программа-конвертер | — | Клиенты, ФОП, документы уже в MEGA SRM |

## Как работает

**Экран «Звіти клієнтів»** (все пользователи):
```
Звіти клієнтів
Клієнт: [ Family Toys ▾ ]   Файл: [ Обрати… ]   → Завантажити
Family Toys · Bagel · «Залишок товару» на 02.11.2026 · 2 магазини
Магазин: [ Усі ▾ | LUXOR PLAZA | Білочка ]
№ | Артикул | Назва (наша)          | К-сть | Стара ціна | Нова ціна | Сума стара | Сума нова
1 | 0905    | Аквакилимок "Кит"     | 2     | 154,10     | [ 160,00 ]| 308,20     | 320,00
…
⚠ Не розпізнано (2): 89999 «Щось чуже» штрихкод 4820288950011  [наш артикул: ____ ]
[ Excel (наш формат) ]  [ Накладна на повернення ]  [ Видаткова накладна ]
```
- Для отчёта о продажах в таблице вместо «К-сть»: залишок на початок, прихід, продано (роздріб), продано (інше), залишок на кінець; документы переоценки строятся по **залишку на кінець**.
- **Наше название** — из каталога SalesDrive (YML) по артикулу; если у артикула несколько товаров (цвета) — название товара «Мікс», иначе первого; если артикула нет в каталоге — название из отчёта клиента с пометкой.
- Повторы (магазин × артикул) складываются; при «Усі» — суммируются по магазинам. Старая цена у повторов одинаковая в образцах; если разная — строки не склеиваются (отдельные строки на каждую цену).

**Документы переоценки** — перед формированием: **Постачальник и Одержувач выбираются вручную** (владелец, 19.11) — в каждом поле список наших ФОП и ФОП этого клиента; подсказка по умолчанию: в накладній на повернення Постачальник = ФОП клиента, Одержувач = наш ФОП; в видатковій — наоборот. Дата (по умолчанию сегодня), **номер — поле**, по умолчанию следующий из счётчика (свой для каждого вида документа × наш ФОП × месяц), можно исправить вручную.
- «Накладна на повернення № N від …» — вид как у видаткової (шапка, таблица со штрихкодом, итоги, прописью, подписи); строки по старым ценам.
- «Видаткова накладна № N від …» — тот же вид, строки по новым ценам.
- Обе сохраняются в «Історії» (тип «Повернення» / «Накладна (переоцінка)»), без заказа SalesDrive; повторное скачивание из снимка; «Анулювати» как обычно.

**Распознавание формата Bagel**: строка заголовков, где есть `Код` и `Назва`; тип — по названию отчёта («Оборот по постачальникам» / «Залишок товару по постачальникам») и набору колонок; магазин — строка «Магазин …» перед блоком; строки товара — где в колонке `Код` число; строки «Разом …», категории, подвал — пропускаются. Количество проверяется по итогу «Разом» отчёта — расхождение показывается как ошибка разбора.

## Решения исполнителя

- Права: всё — всем пользователям (как документы); удаление сопоставлений кодов — только admin.
- Счётчик номера документа переоценки ведётся по **нашему** ФОП (стороне, которая наша — Одержувач в поверненні, Постачальник в видатковій); если обе стороны выбраны не наши — номер только вручную.
- Номера документов переоценки — свой счётчик, поле редактируемое; уникальность номера не навязывается (ручной ввод), но при совпадении с уже выданным номером того же вида — предупреждение.
- Сопоставления кодов хранятся на **клиента** (не на файл): у Family Toys коды общие для обоих магазинов.
- Файлы не хранятся; в истории — только снимок строк документа.

## Оставлено исполнителю

Библиотека чтения .xls (BIFF8) — безопасная для чужих файлов; модель данных (документы без заказа SalesDrive, новый тип «Повернення», счётчики); вёрстка; тексты. Тесты обязательно: разбор обоих образцов (количество строк, магазины, суммы = итоги «Разом»), сложение повторов, сопоставление по штрихкоду и по запомненному коду, ручное сопоставление, нераспознанные строки, суммы документов, нумерация и правка номера, e2e «загрузил остатки → повернення → нові ціни → видаткова».
