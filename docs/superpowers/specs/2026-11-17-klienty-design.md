# MEGA SRM — «Клієнти»: справочник получателей с реквизитами ФОП

Дата: 2026-11-17 · Статус: на утверждение владельцу

## Зачем

Сейчас реквизиты получателя вводятся прямо на экране «Новий документ» и жёстко привязаны к контакту SalesDrive (один контакт — один набор реквизитов). Их нельзя посмотреть списком, исправить отдельно или внести заранее, а у одного клиента (например, сети магазинов) бывает несколько ФОП.

Нужен справочник: вкладка **«Клієнти»**, где создаются клиенты, у каждого — один или несколько ФОП с реквизитами; при формировании документа менеджер просто **выбирает** ФОП получателя.

## Цели

1. Вкладка «Клієнти» (рядом с «Наші ФОП»): список, поиск, создание и правка клиента и его ФОП.
2. У клиента — один или несколько ФОП (назва + многострочные реквизиты).
3. «Новий документ»: выбор получателя из справочника с поиском; по умолчанию подставляется ФОП, выбранный для этого контакта SalesDrive в прошлый раз.
4. Если клиента ещё нет — завести его прямо с экрана документа, не уходя со страницы.
5. Уже введённые реквизиты не теряются.

## Не входит

- Синхронизация клиентов с SalesDrive (запись туда, импорт контактов). У SalesDrive нет API контактов.
- Карточка клиента с заказами, суммами, аналитикой; заметки, напоминания, условия работы.
- Удаление клиентов и ФОП (только архив ФОП).

## Анти-цели (провал, даже если «работает»)

- Пропали или перепутались реквизиты, введённые до этого изменения.
- Исправление реквизитов ФОП меняет уже сформированные документы в истории.
- Менеджеру снова приходится перенабирать реквизиты постоянного клиента.

## Подходы (выбран А, владелец, 17.11)

| | Подход | Плюсы | Минусы |
|---|---|---|---|
| **А ✅** | Клиент → его ФОП; выбор ФОП при формировании; запоминание последнего выбора для контакта SalesDrive | Сети с несколькими ФОП сгруппированы; заранее завести можно; постоянному клиенту выбирать не нужно | Чуть больше работы |
| Б | Плоский список ФОП получателей без клиентов | Проще | При 50–100 ФОП искать неудобно, ФОП одной сети разбросаны |
| В | Оставить привязку реквизитов к контакту SalesDrive + экран просмотра | Минимум изменений | Нельзя завести заранее, один контакт — один ФОП |

## Как работает

**Данные**
- `Client`: назва (обязательно), телефон, комментарий.
- `ClientFop` (уже есть): назва, реквизиты (многострочный текст как в шапке), **принадлежит клиенту**, признак **архив**.
- `ContactDefault`: контакт SalesDrive → ФОП получателя, выбранный для него последним. Обновляется при каждом успешном формировании документа.
- `Document.clientFopId` — как сейчас. Шапка документа уже хранится снимком в истории, поэтому правка реквизитов не меняет старые документы.

**Перенос существующих данных (миграция)**: каждый имеющийся `ClientFop` становится клиентом (назва клиента = назва ФОП) с этим одним ФОП; его контакт SalesDrive записывается в `ContactDefault`. Документы продолжают ссылаться на те же ФОП.

**Вкладка «Клієнти»** (все вошедшие пользователи):
```
Клієнти                                    [+ Новий клієнт]
Пошук: [ babytop            ]   ☐ показати архівні ФОП
▸ BabyTop · 067 111 22 33 · 2 ФОП                 [Змінити]
    ФОП Іваненко І.І.   ІПН 1234567890   [Змінити] [В архів]
    ФОП Петренко П.П.   ІПН 0987654321   [Змінити] [В архів]
  [+ Додати ФОП]
```
Поиск — без учёта регистра, по названию клиента, телефону, названию ФОП и тексту реквизитов (значит, и по ІПН/ЄДРПОУ/IBAN).

**«Новий документ»** — блок «Одержувач»:
```
Одержувач
[ BabyTop — ФОП Іваненко І.І. (ІПН 1234567890)      ▾ ]   ← поиск по вводу
ФОП Іваненко І.І.
Юр. адреса: …
IBAN … в …
ІПН 1234567890
[+ Новий клієнт / ФОП]
```
- По умолчанию выбран ФОП из `ContactDefault` для контакта заказа; если его нет — пусто, кнопки документов неактивны с подсказкой «Оберіть одержувача».
- «+ Новий клієнт / ФОП» — короткая форма прямо здесь: выбрать существующего клиента или ввести нового (назва, телефон) + назва ФОП + реквизиты → сохраняется в справочник и сразу выбирается.
- Архивные ФОП в выборе не показываются.

**Формирование документа**: в запрос добавляется выбранный ФОП получателя (обязателен). Архивный или несуществующий ФОП → понятная ошибка. После успешного формирования запоминается выбор для контакта SalesDrive. Перегенерация документа может сменить получателя (номер сохраняется, как и раньше).

**История**: поиск по клиенту ищет и по названию ФОП, и по названию клиента; в списке колонка «Клієнт» показывает «Клієнт — ФОП».

## Решения исполнителя

- Создавать и править клиентов могут менеджеры (сейчас реквизиты тоже вводят они).
- Нет удаления: ФОП, по которому могли быть документы, уходит в архив; архив можно вернуть.
- Отдельного поля ІПН/ЄДРПОУ нет — он остаётся строкой в реквизитах, как в шапке; поиск по тексту его находит.
- Старый маршрут сохранения реквизитов «по контакту» удаляется; на его место — API справочника.

## Оставлено исполнителю

Вёрстка, имена API, точная форма выбора с поиском, тексты подсказок. Тесты обязательно: перенос данных, выбор и запоминание ФОП, архив, поиск, формирование документа с выбранным ФОП, e2e «новый клиент прямо с экрана документа».
