# «Клієнти» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Справочник клиентов (клиент → один или несколько ФОП с реквизитами) и выбор ФОП получателя при формировании документа вместо привязки реквизитов к контакту SalesDrive.

**Architecture:** Новые модели Prisma `Client`, `ContactDefault`; `ClientFop` получает `clientId` и `archived`, теряет `sdContactId` (перенос данных SQL-ом в миграции). Логика справочника — `src/services/clients.ts`; сервис документов принимает `recipientFopId` и запоминает выбор для контакта. UI: вкладка `/clients`, выбор получателя с поиском на «Новий документ».

**Tech Stack:** как в модуле 1: Next.js 15, Prisma 6 + PostgreSQL, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-17-klienty-design.md`

## Global Constraints

- Интерфейс на украинском: «Клієнти», «Новий клієнт», «Додати ФОП», «Змінити», «В архів», «Повернути з архіву», «показати архівні ФОП», «Одержувач», «Оберіть одержувача», «+ Новий клієнт / ФОП».
- Клиентов создают и правят все вошедшие пользователи (не только admin).
- Удаления клиентов и ФОП нет; ФОП — только архив/возврат.
- ІПН — строка внутри реквизитов, отдельного поля нет.
- Миграция не теряет ни одного существующего `ClientFop` и не меняет `Document.clientFopId`.
- Старые документы не меняются при правке реквизитов (шапка уже снимком в `DocumentVersion.headerJson`).

## Review Focus

1. **Миграция на непустой базе** (прод уже содержит `ClientFop` с `sdContactId`) — данные переносятся, ФОП привязан к новому клиенту, `ContactDefault` заполнен. → Task 1.
2. **Архивный ФОП выбран ранее как default** — не подставляется по умолчанию и не принимается при формировании. → Task 2.
3. **Поиск по ІПН/IBAN внутри реквизитов, разный регистр, кириллица** («babytop», «BabyTop», «1234567890»). → Task 1.
4. **Перегенерация документа с другим получателем** — номер сохраняется, `clientFopId` и снимок шапки обновляются. → Task 2.
5. **Пустые/пробельные поля** (назва клиента «  », реквизиты пусты) → 400 с понятным текстом, не 500. → Task 3.
